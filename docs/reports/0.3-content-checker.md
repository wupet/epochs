# Milestone 0.3: Content checker

This finishes Phase 0. It covers the content checker from the brief, plus the two server fixes you asked for first. The design is in `docs/superpowers/specs/2026-11-19-content-checker-design.md`.

## What was built

- **A tick that fails twice no longer freezes the world.**
  - A failed tick is retried once. If it fails again, its intentions are dropped and the server logs `[epochs] tick failed twice: dropped N intentions`.
  - Anyone whose join was dropped is disconnected, so nobody is left waiting forever, and the next person in the queue gets their slot. The page just shows "disconnected"; reload to rejoin.
  - Any character left in the world without a connection is removed on the next tick.
- **Queue cap.**
  - At most 100 people wait.
  - The next connection is told "The server and its queue are full. Try again later." on the page, and disconnected.
- **Content schemas** (Zod, in `packages/shared/src/content/`) for classes, abilities, items and enemies, using the brief's field outlines.
  - Classes now include a **capstone**: a short description of the class's bonus at full mastery.
  - Typos are caught: unknown fields are errors, and every fixed choice must be one of the listed values.
- **Cross-file checks:**
  - a class's starting abilities must exist;
  - a class's prerequisites must be other existing classes;
  - ids must be unique within each kind.
- **Sample content:** `content/classes/militia.json`, `content/abilities/basic-strike.json`, `content/items/rusty-shortsword.json` and `content/enemies/slime.json`.
- **`npm run check-content`.** It checks everything in `content/` from any folder you run it in, and prints one line per problem: file, field, and what's wrong. It never passes without checking something: if `content/` is missing or empty, it says so and fails. It also works when run through a Windows junction.
- **A smaller page.** The browser doesn't use Zod, so it's left out of the client bundle. The page's main script went from about 104 KB to 80 KB compressed.
- **Docs:**
  - The capstone is in the brief's class outline and the design summary.
  - CLAUDE.md's command list describes `check-content`.
- **Tests:** 311 in 23 files, all passing. The typecheck is clean.

## How to run it

```
npm ci                  # once: Zod is a new dependency
npm run check-content   # All 4 content files are valid.
npm test
```

## What to check by hand

1. Run `npm run check-content`. It should print `All 4 content files are valid.`
2. Break a file, then run it again. For example, set the shortsword's `"kind"` to `"sword"`, add a `"weight": 2` field, and change Militia's starting ability to `"basic-strik"`. This is what I got:
   ```
   content/classes/militia.json: startingAbilities[0]: no ability with id "basic-strik"
   content/items/rusty-shortsword.json: kind: expected one of plain, trait, storied, holy-relic, cursed, consumable, tool
   content/items/rusty-shortsword.json: weight: unknown field
   Found 3 errors in 2 files.
   ```
   The command exits with code 1. Undo your edits afterwards, or run `git checkout content/`.
3. **Queue cap** (optional): this needs 101+ connections. The automated test covers it with a cap of 2, and it reuses the queue you saw working in 0.2.1.

## Things to know

- **The sample values are placeholder drafts.** That covers the numbers (strike damage 10, sword 8 force and 2 precision, slime 20 health, and so on), the names, and the Militia's passive and capstone text, which start with "Placeholder:". Replace them whenever you like; the checker only checks their shape.
- **Fix-then-recheck.** Rules such as "at most 2 damage kinds on an item" and "no repeated damage kind" are checked only once a file matches its schema. A file with a bad choice *and* 3 damage kinds therefore shows the 3-kinds problem on the next run, after the first is fixed.
- **One misleading message to know about.** If an ability file has errors, a class that lists that ability also reports `no ability with id "…"`. That message goes away once the ability file is fixed.

## Design questions

All four were answered by Peter on 2026-11-19.

1. **Are tier and capacity cost linked?** *Answered: yes.* Each tier has a fixed cost: beginner 1, intermediate 2, advanced 3, expert 5. The checker now enforces it (see the follow-up below).
2. **Id style.** *Answered: confirmed.* Ids and fixed choices stay lowercase with hyphens, for all content.
3. **Conditions and passives.** *Answered: yes.* Conditions and signature passives become their own content files in Phase 1. Nothing changes in the code until then.
4. **Damage scale.** *Answered: confirmed.* Whole-number damage of at least 1, and resistance multipliers above 0 (below 1 resists, above 1 is a weakness).

## Follow-up (0.3.1)

- **Tier costs are an error.** A class whose capacity cost doesn't match its tier is reported at `capacityCost`, for example `must be 3 for a advanced class`.
- **Unusual resistance multipliers are a warning.** An enemy resistance multiplier below 0.25 or above 3 is reported as `warning: 4 is outside the usual range 0.25–3`. Warnings are printed but don't fail the check: `npm run check-content` exits 1 only if there is at least one error, and ends with `All <n> content files are valid, with <w> warning(s).` when there are only warnings.
