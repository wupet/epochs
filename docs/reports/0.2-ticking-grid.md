# Milestone 0.2: A ticking grid

## What was built

- **Shared rules** (`packages/shared`, pure and deterministic):
  - **Grid** (`grid.ts`): blocked tiles are a flat list, so they survive being saved or sent.
  - **The step rule:**
    - 8 directions, and a diagonal takes one tick like any other step.
    - No corner-cutting: a diagonal needs both side tiles open.
  - **Route finding** (`route.ts`):
    - It walks to the clicked tile, or to the nearest reachable one when that tile is blocked or walled off.
    - Paths take their diagonal steps first, then go straight.
    - It uses breadth-first search rather than A*, because every step costs the same and the nearest-reachable rule needs a full search anyway. I removed "A* is fine" from the brief.
  - **World state and `step`** (`world.ts`): joins, leaves and moves are all intentions that go through `step`, so a recorded list of intentions replays the whole world, including who joined when.
  - **Wire protocol** (`protocol.ts`): messages carry only each character's id and tile. A character's planned path never leaves the server.
- **Server** (`packages/server`):
  - A 250 ms tick loop that can't drift, because the tick count is worked out from the start time.
  - A 32×32 test map with:
    - wall runs with gaps;
    - a closed room in the top right;
    - two diagonal pinches, where two walls touch only at a corner.
  - WebSockets at `/world`. Each tab gets a square, and each tick every tab gets only what changed.
  - Every client message is validated, and bad ones are ignored without dropping the connection.
  - If port 8787 is already taken, it now says so and exits instead of crashing.
- **Client** (`packages/client`, PixiJS 8):
  - Draws the grid: your square is gold and others are blue.
  - Click to move.
  - Hover shows the path, using the same `findRoute` as the server.
  - After a click, a cross marks where you'll end up.
  - Squares slide between tiles.
  - A tick pulse flashes faintly. **P** toggles it, and `?pulse=0` starts with it off.
  - A status line shows connection state and the tick number.
- **Purity guard:** a test fails if any file in `packages/shared` uses `Math.random`, `Date.now` or `new Date`. It ignores mentions in comments, but not calls hidden after a `//` inside a string.
- **Docs:** your decisions are recorded in `docs/phase-0-brief.md` and `docs/design-summary.md`: diagonals, the corner rule, nearest-reachable, and passing through each other. My interpretations are marked separately.
- **Tests:** 162 in 18 files. These include:
  - route finding with every tie-break;
  - determinism over 60 ticks of scripted joins, moves, re-routes and leaves;
  - the tick loop over a simulated hour with every wake-up late, ending with exactly 14 400 ticks;
  - server tests with real WebSocket clients, including a check that one client never receives another's path.

New dependencies: `pixi.js` 8.23.0 (client), `ws` 8.23.0 and `@types/ws` 8.18.2 (server). The lockfile only gained entries.

## How to run it

```
npm ci            # once, after pulling (new dependencies)
npm run dev       # http://localhost:5173
npm test
npm run typecheck
```

## What to check by hand

1. **Two tabs.** Run `npm run dev` and open http://localhost:5173 in two tabs. Each tab shows its own square in gold and the other in blue.
2. **Hover.** Move the mouse over a tile. A path appears from your square, and the end tile is outlined.
3. **Click.** The square walks there one tile per tick, sliding. The cross disappears when it arrives.
4. **Re-click mid-walk.** The square should turn on the next tick, which is at most a quarter second.
5. **Click inside the closed room** (top right). The square walks to the nearest tile outside it, marked with the cross.
6. **The diagonal pinches** are two black squares touching at a corner, one near the middle and one lower left. Click across one. The path goes around the pinch, not between the two walls.
7. **Tick pulse.** Watch for the faint flash and press **P** to toggle it. Try `http://localhost:5173/?pulse=0`.
8. **Ctrl+C** in the terminal stops both processes. The checks in the 0.1 report still apply. I re-ran the automated Ctrl+C test with the new server: 4 of 4 passed.

## What I measured, and what you need to judge

**Measured in Chrome**, with a second watch-only connection logging every tile the square stepped on:

| What | Result |
| --- | --- |
| Movement | One tile per tick, every tick |
| Course change | The second click came 156 ms before the next tick, and that tick already turned the square around |
| Time from click to first step | 18 ms and 156 ms in two tries, which is however long until the next tick, up to 250 ms, plus network time |
| Tick arrival in the browser (over 436 ticks) | Mean 250.0 ms; 95% within 265 ms. One gap of 489 ms and one double arrival, both while the tab was in the background or being screenshotted |
| Errors | None in the browser console or the server log |

**What I couldn't measure: smoothness.** Chrome slowed animation frames to about one per second in the window I was driving, and each screenshot took several seconds, so I never saw the slide at full frame rate. Please judge these by eye:

- **Does the slide look continuous, or does it hitch at each tile?** Each slide lasts exactly one tick (`TWEEN_MS` = 250 ms in `packages/client/src/motion.ts`). When a tick arrives late, the square waits on its tile until it does. With the jitter I measured (about ±15 ms), any pause should be too short to see. If you do see a hitch, that's the first thing to tune.
- **Does a click feel responsive?** Up to a quarter second can pass before the first step, because the step waits for the next tick. That is the price of a 0.25 s tick. Client-side prediction could hide it later, with the server still deciding.
- **Is the pulse too much?** It flashes the whole grid white at 12% strength for 120 ms (`PULSE_STRENGTH` and `PULSE_MS` in `packages/client/src/pulse.ts`).
- **Do paths look natural?** Diagonal first, then straight. Around walls, the path can go diagonal, then straight, then diagonal again.
- **Is 4 tiles a second the right speed?**

**What I'd tune, in order:**
1. **If you see a hitch:** raise `TWEEN_MS` slightly, to about 270, so slides overlap instead of pausing. If that isn't enough, switch to buffered interpolation, which draws a fixed one tick behind. That is perfectly smooth but adds 250 ms of delay.
2. **The pulse:** lower `PULSE_STRENGTH` to about 0.06, or pulse only the grid border instead of the whole grid.
3. **Sharpness on a scaled display:** the canvas doesn't use the screen's pixel density yet, so on Windows scaling above 100% the grid may look slightly soft. It's a one-line fix.

## Anything that felt off

- **Missed ticks run all at once.** If the server stalls (a laptop sleeping, say), it runs every missed tick in one burst when it wakes. There is no cap yet.
- **The search covers the whole map.** I believe RuneScape only looks within about 10 tiles of the click. That's cheap at 32×32, but the 64×64 regions will need a limit.
- **There's no reconnect.** If the server restarts, the tab shows `disconnected`; reload the page.
- **The cross can stay forever.** If you never reach the destination, it stays until your next click.
- The reviews also found some smaller polish items, which I'm triaging in the final review.

## Design questions

1. **What does "nearest" mean when the target is unreachable?** I measure straight-line distance (dx² + dy²). Because of that, a tile diagonally away counts as further than one straight across. After your shorter-path rule, any remaining tie goes to the tile higher on the map, then further left. Is that right, or should a diagonal tile count as 1 step away, like movement?
2. **Path shape.** Among equally short paths, the square walks diagonally first and then straight. Is that the look you want?
3. **Spawning.** New characters appear on the nearest free tile to the spawn point, so tabs spread out. Players can still share tiles afterwards.
4. **Search range.** Should the nearest-reachable search have a range limit, like RuneScape's?
5. **Missed ticks.** Should a stalled server catch up all missed ticks, or skip them?
